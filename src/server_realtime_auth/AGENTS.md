# DOX: src/server_realtime_auth — Realtime Data Server

## Purpose

Core realtime data server for JSON-SCADA. Handles client connections, JWT authentication, real-time data streaming from MongoDB Change Streams, user session management, and action queue processing. The primary API gateway for the web UI.

## Ownership

- server_realtime_auth owns the realtime data serving infrastructure
- All web UI clients connect through this server

## Local Contracts

- **Language:** Node.js
- **Main entry:** `index.js`
- **Auth:** JWT (JSON Web Tokens). The token only identifies the user (`id`, `username`, `tv` token version, `jti`); rights never come from it. `services/user-rights.js` reads the current rights (10 s cache, in-flight lookups shared, `invalidate()` after user/role changes, `{ fresh: true }` for commands and `isAdmin`) and refuses deleted users, revoked tokens (`revokedTokens` collection, sign-out) and tokens older than the user's `tokenVersion` (bumped by password changes). `invalidate()` bumps a generation: lookups started before it neither cache their answer nor are joined afterwards. GraphQL admin fields and commands share one fresh lookup per operation (`freshRights(ctx)` in `graphql-server.js`); a database outage is `SERVICE_UNAVAILABLE` there and `BadServerNotConnected` for `/Invoke/` commands, never a missing right. Database trouble serves cached rights at most 60 s old for fresh lookups and 10 min old otherwise (`MAX_STALE_FRESH_MS`/`MAX_STALE_MS`), else raises `RightsUnavailableError`: answer 503 / `BadServerNotConnected`, never a rejection (the AdminUI keeps the session on `unavailable: true`). Sign-outs made here stay in `localRevoked` (jti → expiry) until the token expires, so a refresh that read the collection earlier cannot drop them; those not stored (`unstored`, database unavailable) are stored by the 10 s revoked-token refresh once the database is back. `authJwt.verifyToken` sets `req.token`/`req.rights`. `JS_JWT_SECRET` unset means a random per-process secret. Sign-in is throttled in memory (5 failures per client address+user, or 30 per address, lock 15 min; at most 8 password checks at once and 2 per address, else 503; client address from `services/client-address.js`, which believes proxy headers only from `JS_TRUSTED_PROXIES`); failures are audited as `signinFailed`. A trusted proxy on another host must be listed in `JS_TRUSTED_PROXIES` exactly as the socket peer address, or all its users share one throttle key. Passwords set here need 8+ characters; lower-cost bcrypt hashes are rehashed at sign-in. Local users (`isLDAPUser` false) are checked locally only, LDAP users by the directory only; `authenticateWithLDAP` refuses a directory name that matches a local user. LDAP sessions are capped by `ldap.maxSessionHours` / `JS_LDAP_MAX_SESSION_HOURS` (default 12, the directory is only read at sign-in). `remainingAdmins` in `auth.controller.js` refuses role updates, role removals and user deletions that would leave no user with an `isAdmin` role; the `admin` user cannot be renamed or deleted; a real rename also `$inc`s `tokenVersion` (tokens carry the name used for the audit trail and Grafana). `deleteProtocolConnection` deletes the connection by scalar `_id` first and then only the tags of its stored `protocolConnectionNumber` (no MongoDB transaction: standalone installs have no replica set). Command status (GraphQL `commandStatus`, `/Invoke/` EventNotifier ack read) goes through `canSeeCommand` (`services/command-guard.js`): originator, admin, or station access to the command point. `updateUser`/`updateRole` write only allowlisted plain fields (`USER_UPDATE_FIELDS`/`ROLE_UPDATE_FIELDS`) with `$set`; a password change (admin `updateUser` or self-service `changePassword`, the latter conditioned on the checked hash) sets the hash and `$inc`s `tokenVersion` in one write; tag, connection and driver-instance updates drop `$`-prefixed and dotted keys (`withoutOperators`); all need a scalar `_id` (`scalarId`). Node-RED, n8n, log-io and supervisor proxies (HTTP and websocket) are admin-only; websocket upgrades refuse a foreign `Origin` (`sameOrigin` in `proxy-utils.js`; the log names a proxy that dropped the port from `Host`, nginx must forward `Host $http_host`) and an open one is re-checked every 30 s and closed when the token expires, is revoked or loses `isAdmin`; `stripSessionToken` (`proxy-utils.js`) removes `x-access-token` (cookie and header) from every proxied request; `/custom-developments` needs a session (`authJwt.isUserPage`, redirects to `/login`); `jwt.verify` accepts HS256 only; the mutating create/update/delete tag, connection and driver-instance routes are POST-only. `createUser`/`createRole` take only allowlisted fields (`roles` must be ids of existing roles); delete routes and `userAddRole`/`userRemoveRole` need a scalar `_id` or string names. Startup ensures the unique indexes `users.username` (`userNameIndex`) and `roles.name` (`roleNameIndex`), as the seed does (duplicates already stored are logged). User names are unique
- **Commands:** `/Invoke/` and GraphQL read the command point with `app/services/command-guard.js` (`findCommandPoint`, primary read, projected) and refuse with `commandRefusal`: origin not `command`, or the point or its `supervisedOfCommand` point blocked (`commandBlocked` true or a non-empty `annotation`), the same rules as the MCP and OPC UA server command paths. A Double command needs a finite number
- **Point ids:** a `NodeId.Id` / `tagOrId` is a point key only when it is a number or a digit string (`asPointKey` in `index.js` and `graphql-server.js`); anything else is a tag name. Never use `parseInt` for this. Tag names therefore never begin with a number or a signed number: `createTag`/`updateTag` refuse them (`isValidTagName`) and trim the name
- **Station and display restrictions:** a user's `group1List` is part of the database query for reads (also `ContentFilter` reads, which are projected to `FilteredReadFields` and capped at `MaxFilteredReadRows`), events, history, `/queryJSON` rows and property writes in both `/Invoke/` and GraphQL; `displayList` is enforced on `/svg/*.svg`, names with `:` `\` or a trailing dot/space refused for restricted users (the `json-scada-user` cookie drops a list that would push it over 3500 bytes and sets `rights.displayListTruncated`; clients then call `GET auth/userDisplays`, as the AdminUI Display Viewer does in `src/lib/screenList.js`); commands follow `UserRights.canCommandGroup` (`group1CommandList`, else `group1List`, both when both are given; `$$` needs `$$` in the command list when the user is restricted by either list)
- **Config:** INI file via Supervisor or environment variables
- **Request handling:** one MongoDB pool (the native handle of the mongoose connection, `db` in `index.js`). Body limit 2 MB, 100 MB only on the project import, CIM-EMS upload/request and display save routes (token checked first; GraphQL checks the token before its own 50 MB parser and limits query depth to 10, introspection subtrees `__schema`/`__type` to 30, validation work to 5000 selections, top-level fields to 50 (`rootFieldsRule`); fragment depths are memoized; every list resolver takes its limit from a 500000-row request budget, `budgeted`/`reserveRows`/`configPage`/`groupPage` in `graphql-server.js`; `User.roleDetails` reads all roles once per request, `rolesById`); proxied apps get unparsed streams. User actions are queued in `userActionsQueue.js` (bounded to 100000, oldest dropped; `enqueue` replaces any property named like a password, passphrase, secret, token, credential or api key with `***` at any depth; objects/arrays below depth 20 become `[too deep]`) and written in ordered `insertMany` batches of 500 by a 1 s flusher that removes only the stored entries, by identity (`ack`), so an overflow during an insert cannot remove an unwritten entry, and once more on SIGTERM/SIGINT/uncaught exception. Writes nobody waits for end with `.catch(logBgError)`; unhandled rejections are logged, not fatal. A last Express error handler answers JSON without internals. Per-request log lines use `Log.levelDetailed`. One PostgreSQL pool (`pg-pool.js`, connect/statement timeouts `JS_PG_CONNECT_TIMEOUT_MS`/`JS_PG_STATEMENT_TIMEOUT_MS`) serves `/Invoke/` and GraphQL; `/Invoke/` HistoryRead and GraphQL `historicalData` limit rows per tag (LATERAL query); HistoryRead takes at most 1000 nodes (`MaxHistoryNodes`), reads each tag once and caps the answer at 200000 samples (`MaxHistorySamples`, repeated nodes count again). User rights, revoked tokens, sign-in lookups and the admin guard read the MongoDB primary even when `JS_SERVER_REALTIME_AUTH_READ_FROM_SECONDARY` is set. Multipart uploads use temp files (`UPLOAD_TMP_DIR`), removed when the response ends; project import and export share one lock (`takeProjectLock`), taken before anything is written to `tmp` and held until their files there were used and removed (the scripts use the fixed `tmp`); a project import needs `users.json`/`roles.json` with an admin user (`projectAdminProblem`) and invalidates the rights cache. CIM-EMS: at most 20 pending requests per user (429). Admin route errors go through `errorText` (no raw error objects); `simple-logger.js` indents continuation lines so request data cannot forge log entries; a missing/invalid config file exits with code 1 SIGTERM/SIGINT stop accepting connections and give requests 5 s before the audit flush and exit; a failed MongoDB connect at startup exits with code 1. Responses carry `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin` and, outside the proxied prefixes and unless `JS_ALLOW_FRAMING=true`, `X-Frame-Options: SAMEORIGIN`. `/GetFile` takes its content type from the file name (`mime` only for passive types, `SAFE_GETFILE_MIME_RE`) and sandboxes html/svg/xml/script content. `AdminUI/dist/assets` (content-hashed) is served with a 1 year immutable cache. `listDisplays`/`openDisplay`/`saveDisplay` use one display folder (`SVG_DIR`, resolved from the source file, not the working directory) and only plain `.svg` names (`displayPath`, no `:`); `saveDisplay` audits name and size; a `/Invoke/` WriteRequest takes at most 100 `NodesToWrite` (`MaxWriteNodes`, else `BadTooManyOperations`); sign-out is audited only for a valid token, without the body Exported/imported project zips and the extracted import files are deleted from `tmp` after use; an import script ending with a non-zero code is reported as an error; uploads over 10000 entries or 1 GB unpacked are refused. Queries built from request data accept only scalar values and plain field names (`ContentFilter`); `listTags`/`listUserActions` pages are at most 1000 and their filters plain fields with a few comparison operators (`listFilter`); point property writes are checked by `services/point-properties.js` (types, annotation at most 2000 and notes 10000 characters, finite limits, hysteresis not below zero), a refused node gets `BadTypeMismatch` and nothing is written; GraphQL errors carry no stack traces; the group1 restriction of the user is part of the database query for events and point property writes. An uncaught exception ends the process (the process manager restarts it)
- **CIM-EMS:** `app/controllers/cimEms.controller.js`, routes `/Invoke/auth/cimEms/*` (list models, bindings, runs, requests; `uploadModel`, `request`, `artifact`). All need only a signed-in user (`authJwt.isUser`, not admin); model, binding and artifact actions also need a role with `cimEngineering` (`authJwt.isCimEngineer` / `hasCimEngineering`). The server only stores uploads/binding sets in the `cimArtifacts` GridFS bucket and queues `cimStudyRequests`; the CIM-EMS driver executes them (`src/cim-ems/cim_ems/api.py`), so request shapes change together. Every request and download is logged as a `cimEms:<type>` user action. `/GetFile` refuses the `cimArtifacts` bucket
- **Realtime Read extension:** a `NodesToRead` entry with `_ValueJson: true` also gets the point's `valueJson` in `_Properties.valueJson` (`null` when absent), on both Value and Description reads; other entries never carry it. Used by the AdminUI Display Viewer for `!JSON` markup
- **Point property writes** (`/Invoke/` WriteRequest, `AttributeId` Description, `Value._Properties`): each field is changed only when present and the user's roles grant its right (`enterAnnotations`, `disableAlarms`, `enterLimits`, `enterNotes`, `substituteValues`); fields without the right are skipped silently. A `null` `loLimit`/`hiLimit` (an Infinity serialized as JSON) means no limit (stored as -Infinity/Infinity)
- **Communication status tags:** `createTag`/`updateTag`/`deleteTag` refuse tags carrying `commStatus` (or named `_System.Driver.`/`_System.Conn.`/`_System.Comm.`) — no create or delete, no change to `tag`, `type`, `origin`, `commStatus`, groups or descriptions; other fields stay editable. The generator is `cs_data_processor` (see `docs/schema.md`)
- **Configuration prune:** `auth/pruneConfiguration` (admin, `pruneConfiguration` user action) is a dry run unless `confirm: true`; it deletes every protocol connection (scheduling the affected driver restarts), every tag except reserved keys -1/-2, `origin: "system"`, `commStatus` and `_System.*` tags (or, with `tags: false`, only the tags of the pruned connections), all CIM-EMS collections and the `cimArtifacts` bucket, and the shipped example displays matched by `DEMO_DISPLAY_RE` in `auth.controller.js`; parts are skipped with `connections`/`tags`/`cimModels`/`displays: false`. Driver/process instances, users, roles and settings stay
- **Process management:** `app/services/process-manager/` runs `supervisorctl`/`nssm` without a shell; errors meant for the admin are `ProcessError` (`exec.js`) and are answered as they are, others only logged (`errorText` in `processManagement.controller.js`). `supervisorctl` gets its server URL and credentials from a private `[supervisorctl]` file (`-c`, 0600 in a 0700 temp folder removed at exit), never `-u`/`-p` arguments. Instances are referenced by a scalar `_id` or a string driver name with an instance number (`resolveInstance`); concurrent status polls share one refresh (`statusRefresh`).
- **MCP server service:** `auth/getMcpServer`, `auth/updateMcpServer` and `auth/controlMcpServer` (admin; `updateMcpServer` and `<action>McpServer` user actions) manage the HTTP service of `src/mcp-json-scada-db`. Settings live in `systemSettings` `{ "key": "mcpServer" }` (`app/services/mcp-settings.js`: validated fields only, the password stored for the MCP server but answered only as `adminPasswordSet`; the MCP server reads them at startup, keep the field names in step with its `jsonscada/service-settings.ts`). Start/stop/restart go through `ProcessManager.coreControl('mcp', ...)`, which only controls the platform-installed service by name (`JSON_SCADA_mcp_server` / `mcp_server`) and never creates, rewrites or removes it. `getMcpServer` also reports whether the configured address accepts TCP connections on this host and whether the sign-in user exists with an `isAdmin` role
- **CIM-EMS services:** `auth/getCimEmsService`, `auth/controlCimEmsService` (body `service`: `main` or `demoField`, and `action`) and `auth/installCimEmsDependencies` (admin; `<action>CimEmsService` and `installCimEmsDependencies` user actions). Start/stop go through `ProcessManager.coreControl('cimEms' | 'cimEmsDemoField', ...)` (by name only: `JSON_SCADA_cim_ems` / `cim_ems`, `JSON_SCADA_cim_ems_demo_field` / `cim_ems_demo_field`); start and restart are refused while the Python environment is missing or being installed. `app/services/cim-ems-env.js` checks the interpreter the services run (Linux `src/cim-ems/.venv`; Windows `platform-windows/python-runtime`, else the `.venv`) against the package and pins of `src/cim-ems/pyproject.toml` (`ok`, `outdated`, `missing`, `unsupported` off x64 Linux/Windows, `unknown`; cached 60 s), and runs the component's `install.sh` / `install.bat` as one background job (no request data on the command line, 30 min timeout, output kept in memory and appended to `log/cim_ems_install.log`). An install is refused while either core service or any managed CIM-EMS driver instance runs
- **API consumers:** the `/Invoke/auth/*` admin routes (sign-in cookie `x-access-token`, `{ error }` responses, driver instance/connection/tag CRUD, process management, system settings, MCP server service, CIM-EMS services, restart scripts, users/roles, displays, project export/import, configuration prune, `cimEms/*` CIM-EMS routes) and the realtime `/Invoke/` WriteRequest (alarm/event acknowledgement, point properties) are also called by `src/mcp-json-scada-db` (`jsonscada/admin-api.ts` and the admin and operator tools); keep request/response shapes compatible or update the MCP tools with them

## Work Guidance

- Clients poll the OPC-like `/Invoke/` API (read, write, history); there is no WebSocket data stream or change stream here (websocket upgrades exist only for the proxied editors)
- JWT tokens are issued on login and verified on every request, with the user's current rights
- The user action queue stores the audit trail; it redacts secret-looking field names, but do not rely on it for secrets under other names, and never queue a user name the request merely claims (pass the account's: `registerUserAction(req, action, { username, noBody, body })`)
- The GraphQL endpoint (`/apollo`) provides an alternative query interface with the same rights
- Supports RBAC (role-based access control) per user/role configuration; add new role flags to `services/user-rights.js` `combineRights`
- Keep the historian pool (`pg`) alive across errors: it reconnects by itself

## Verification

- `npm install` — dependencies install cleanly
- `node index.js` — server starts and listens on configured port
- Verify JWT login flow (admin/jsonscada default credentials); an admin route without a token answers 403
- Verify a `/Invoke/` read of a point and an annotation write by a user restricted to some group1
- There is no automated test suite: check against a running server (a throwaway `mongo` container with a seeded user and role is enough)

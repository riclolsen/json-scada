# DOX: src/AdminUI — Web Admin Interface

## Purpose

Vue.js single-page application (SPA) for the JSON-SCADA web administration interface: real-time data visualization, configuration management, SVG synoptic displays, user management, and protocol monitoring.

## Ownership

- AdminUI owns all Vue components, routing, state management, styles, and the Vite build configuration
- All changes to the web interface happen here

## Local Contracts

- **Framework:** Vue 3 + Vuetify 4 with Vite build tool
- **Typography:** Vuetify 4 has only the Material 3 classes (`text-display-*`, `text-headline-*`, `text-title-*`, `text-body-large|medium|small`, `text-label-*`). The Vuetify 2/3 names (`text-h1`…`text-h6`, `text-subtitle-*`, `text-body-1/2`, `text-caption`, `text-overline`, `text-button`) do nothing. Plain `h1`…`h6` elements keep the browser's default size and margins
- **Package manager:** npm (see `package-lock.json`)
- **Linting:** ESLint 10 flat config `eslint.config.mjs` (`@eslint/js` recommended + `eslint-plugin-vue` essential; `npm run lint`, which also fixes) + Prettier (`.prettierrc.json`)
- **Browser targets:** defined in `.browserslistrc`
- **Build output:** `dist/` directory, served by Nginx (see `conf-templates/nginx_*.conf`)
- **Dev server:** `npm run dev` (Vite, http://localhost:3000)
- **Production build:** `npm run build`
- All API calls go through the realtime data server (JWT auth)
- The readable `json-scada-user` cookie (set by `server_realtime_auth` at sign-in) carries the user's flags and `rights.displayList`; when `rights.displayListTruncated` is true the list was too long for a cookie and must be read from `GET /Invoke/auth/userDisplays`. `lib/screenList.js` lists only those displays (unless `rights.isAdmin`; the server also enforces them). A server answer with `unavailable: true` (database down) keeps the session
- Settings kept across reloads are per user: read and write them with `getUserSetting` / `setUserSetting` (`lib/viewerHelpers.js`, key `<key>@<username>` from the `json-scada-user` cookie, falling back to the old shared `<key>` until the user saves). Events Viewer: `eve_settings` (mode, unchecked stations, historical filter, key columns), `gpstime`, `eve_fontsize`; Tabular/Alarms Viewer: `almFilter` (station and priority filter; priorities as plain number strings), `tab_fontsize`; Alarms Viewer: `alm_settings` (mode, visible columns, unacked only, historical filter); Security Events viewer: `sec_settings` (minimum severity, categories, auto refresh); Admin lists: `admin-pref-*` (`loadPref` / `savePref` in `lib/adminList.js`: page sizes, Tags columns, Roles view); side panel `nav-rail`; theme `user-theme` and language `user-locale`, which also write the plain key (`alsoShared`) as the browser's choice for the sign-in page; `App.vue` and `AppSidebar.vue` re-read them when a user signs in. Never call `localStorage` directly for a setting
- Vue component naming: PascalCase. Single-file components with `<script setup>` preferred
- Styles: scoped CSS. Global styles in `src/` root
- Locales: `src/locales/*.json` (13 files) carry the same keys; add every new key to all of them
- Display Viewer engine (`lib/sage/`): `!JSON <tag> <path>` tag references and the `$J(tag, path)` script function read members of a point's `valueJson` (path syntax in `lib/sage/sageJson.js`, mirrored by `src/mcp-json-scada-db/src/jsonscada/json-path.ts`; markup in the svg-scada skill section 10). The engine requests `valueJson` only for those points, through the `_ValueJson` node flag of `opcClient.readPoints` (served by `server_realtime_auth`). Likewise `!STR <tag> <selector>` / `$S(tag, selector)` take parts of the raw `valueString` (returned on every read; selector grammar in `lib/sage/sageStr.js`, parsed and never evaluated, mirrored by `src/mcp-json-scada-db/src/jsonscada/str-select.ts`; skill section 11). Both share `memberState` for display semantics
- Viewers are native Vue pages (no iframed legacy HTML): `/display-viewer` (`?screen=<name>`), `/tabular-viewer`, `/alarms-viewer` (`AlarmsViewerPage`: the `alarmsData` alarm list through `opcClient.readAlarms` / `POST auth/listAlarms`; realtime Normal lists unacknowledged or active alarms and Aggregated keeps the newest occurrence per tag from that feed before applying the grid filters. Grid counts and filter chips use the selected mode. A row click in Normal acknowledges one occurrence. Aggregated marks a row unacknowledged if any loaded occurrence for the point is unacknowledged and sends a point-wide `writeAck` without an alarm ID when clicked. F8 acknowledges all in both realtime modes; historical mode queries a period with a text filter, `?mode=historical`; the former point-based alarm mode of `TabularViewerPage`, `?mode=ALARMS_VIEWER`, is kept), `/events-viewer` (`?modo=4` historical), `/sec-events-viewer` (`SecEventsViewerPage`: the `secEvents` collection through `POST auth/listSecEvents`, period, minimum severity, categories and text filter, counts per severity, 10 s auto refresh of an open period, CSV export, row click shows the whole document), `/trend-viewer` (`?point=<key or tag>`; `TrendViewerPage`, history from `opcClient.readHistory` plus 5 s live reads). The former `/*-viewer-new` paths redirect to these
- Viewer lifecycle: every route is bundled up front and pages are unmounted on navigation, so a page's timers must stop on unmount. Pages whose `onMounted` awaits before starting timers or listeners, or whose poll reschedules itself after an `await` (`pollTick`, `statusTick`, SageEngine `refresh`/`loadScreen`), set a `disposed` flag in `onUnmounted` and check it after every `await` and before every reschedule; a self-rescheduling poll also clears `pollTimer` before setting it, as other handlers (mode change, ack) may have scheduled one meanwhile. SageEngine `loadScreen` also stops when a newer load started (`loadSeq`)
- Navigation is the left side panel `components/AppSidebar.vue` (there is no top app bar): menu entries come from `lib/navItems.js` (`route` opens in the same window, `page` in a new one; `adminOnly` entries need `rights.isAdmin`, `right` entries that right, e.g. the Security Events viewer `viewSecEvents`, `rightOrAdmin` entries either, e.g. the SVG Editor `editDisplays`; `App.vue` passes the cookie rights to `AppSidebar`, overridden by the current boolean rights answered by the 15 s session check `GET /Invoke/test/user`, so role changes show without signing in again); every entry also opens in a new window from its arrow button, Ctrl/middle click, or the hover flyout when the panel is collapsed to icons (state in `localStorage` `nav-rail`). The footer holds the user menu (change password, logout), language, theme, About and collapse; on small screens the panel slides in from a floating menu button. `/dashboard` is a welcome page. Menu icons are the stroke set in `components/NavIcon.vue` (24 px grid, 1.75 stroke, `currentColor`); add new icons there
- Pages fill the viewport height (`100vh`) beside the panel; pages of separately served tools (Grafana, Node-RED, n8n, Apollo, Metabase, SVG editor, log viewer) are full-height iframes. Custom Developments (`components/CustomDevelopmentsPage.vue`) is a native page: a card grid from `GET /custom-developments?format=json` (title, description, build date of each app; search from 4 apps), an app opens framed under a back/reload/new-window toolbar (`?app=<folder>`), or in a new window. The document scrolls (`html { overflow-y: auto }` in `App.vue`). Pages must not change `html`/`body` overflow, in unscoped CSS or at runtime: every route is bundled up front, so such a rule would apply to all pages
- `?embed=1` on any route hides the side panel (`App.vue` provides `embedded`), for pages used inside iframes (Display Viewer hover previews, `#foreign_object`) and popups. The Display Viewer also hides its toolbar and keeps `embed` when it changes screen; `/trend-viewer?controls=0` hides the trend toolbar (hover preview of an analog reading)
- `public/` holds static files only, served at the site root: `images/`, `sounds/`, `favicon.ico`, `release_notes.txt` (shown by the About page; a copy of `platform-windows/release_notes.txt`, update both together), `conf/config_viewers.js` (site overrides read by `lib/viewersConfig.js`), `camera.html` + `lib/jsmpeg.min.js` (`#camera` stream page, see `src/camera-onvif`). Do not add legacy jQuery viewers or libraries back there
- Admin page (`components/AdminPage.vue`, `/admin?tab=<users|roles|drivers|connections|tags|userActions|system>`): one sticky row with the title and the section tabs (each tab's tooltip describes its section), with the active section kept in `?tab`. The section lists share the toolbar/filter/table/dialog classes (`admin-*`, defined in `AdminPage.vue`), the summary tiles of `components/AdminSummary.vue` (a tile with `filter` toggles that list filter) and the `lib/adminList.js` helpers: JSON posts, paged bulk reads, CSV export (up to 100 000 rows over 1000-row pages), and per-browser preferences (`localStorage` `admin-pref-*`). Polling and auto refresh (5 s) run only while the section is shown
  - Tags and User Actions filter on the server: `listTags` / `listUserActions` take a field filter limited to the operators of `listFilter` in `server_realtime_auth` (no `$not`, `$or` or nested logic). Users, Roles, Driver Instances and Connections read their whole list and filter it in the browser
  - Users and Roles share `lib/roleRights.js`: the boolean rights with their labels and icons, `MIN_PASSWORD_LENGTH` (mirrors the server), and `effectiveRights`, which must combine roles like `combineRights` in `server_realtime_auth/app/services/user-rights.js`. A new user is created in one `createUser` call (roles as ids). An edit calls `updateUser`, then `userAddRole` / `userRemoveRole` by role name, one at a time. The roles rights matrix saves each toggle with a partial `updateRole`
  - Liveness comes from the data processor's communication status tags (`docs/schema.md`). Connections use `_System.Conn.<name>.*` (status, tag count, health) and fall back to `stats.isConnected`. Driver instances use `_System.Driver.<driver>.<n>.Alive` and fall back to a keep-alive younger than 30 s by the browser clock
  - System (`components/SystemSettingsTab.vue`) holds these cards:
    - **Counts:** totals of tags, connections, driver instances, users, roles and displays.
    - **Project backup:** export and import. The export file name must match the server's plain zip-name rule, and a response that is not a zip file (it starts with `PK`) is treated as a JSON `{ error }`. An import replaces the whole configuration, so it needs a confirmation.
    - **Service management:** the system settings, saved on change.
    - **Data retention:** days kept for `soeData`, `alarmsData`, `secEvents` and `hist` (`soeRetentionDays`, `alarmsRetentionDays`, `secEventsRetentionDays`, `histRetentionDays`; whole numbers within the `retentionLimits` answered by `getSystemSettings`), saved with its own button through `updateSystemSettings`; the data processor applies them once a day.
    - **Restarts:** restart protocols or processes, each confirmed.
    - **Configuration clean-up:** `pruneConfiguration`, always as a dry-run preview first. Deleting needs the word `PRUNE` typed in.
    - **MCP server** (`components/McpServerCard.vue`): state, client address and start/stop/restart of the MCP HTTP service, and its settings (`getMcpServer` / `updateMcpServer` / `controlMcpServer`). The stored password is never read back: an empty field keeps it. A poll keeps unsaved edits; Save and restart applies a change at once (the MCP server reads its settings only at startup).
    - **CIM-EMS** (`components/CimEmsServiceCard.vue`): start/stop/restart of the `cim_ems` driver and `cim_ems_demo_field` services and the Python environment check (package table against the pinned versions) with an install button that runs the component's install script (`getCimEmsService` / `controlCimEmsService` / `installCimEmsDependencies`). Start is disabled while packages are missing, install while a CIM-EMS service runs; the poll runs every 2 s during an install and shows its output.
  - Tags edit dialog, calculated points (`components/CalculatedPointEditor.vue`): formula picked from `lib/calcFormulas.json` (code, name, expression, parcel rule, result, quality, notes; legacy formulas behind a checkbox; any code can still be typed, codes from `userFormulaMin` are user processes) and parcels as an ordered list of point keys with tag name, description and value, added by a `listTags` search on tag name, description or key. `lib/calcFormulas.json` is generated from `src/mcp-json-scada-db/src/jsonscada/calculations.ts` by `node tools/gen-calc-formulas.mjs`, never edited by hand
  - Cross-section links pass a filter object through `AdminPage`: Roles → Users of a role, Driver Instances → Connections of an instance, Connections → Tags of a connection
  - Clone opens the new-item dialog with a copy of the item's configuration. A tag copy gets the next free point key and leaves out runtime fields; a connection copy gets the next free number; a role copy gets `_copy` appended to its name. Communication status tags cannot be cloned or deleted
- `components/CimEmsPage.vue` (route `/cim-ems`, side-panel entry, open to any signed-in user) hosts `components/CimEmsTab.vue`, the CIM-EMS UI; it talks only to `/Invoke/auth/cimEms/*` (see `src/server_realtime_auth/AGENTS.md`) and waits for driver-executed requests by polling `listRequests`

## Work Guidance

- Use upright text throughout the Alarms Viewer grid in both realtime and historical modes
- The Alarms Viewer always shows Description, Value (recorded alarm value), and Priority. Its column menu saves the optional columns per user across modes. Without a selection, Historical adds return and acknowledgment details to the realtime defaults. A saved legacy Key toggle maps to all optional columns when enabled.
- Maintain responsive design for mobile/tablet/desktop
- Use existing components and patterns when adding features
- SVG synoptic displays use the `svg-scada` skill conventions (JSON in `inkscape:label`)
- Internationalization (i18n): use established patterns in the codebase

## Verification

- `npm install` — install dependencies
- `npm run build` — production build must succeed with no errors
- `npm run lint` — lint check
- `node tools/gen-calc-formulas.mjs --check` — the formula picker catalog matches the calculations formula table
